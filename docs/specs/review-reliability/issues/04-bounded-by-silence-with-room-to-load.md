# 04 — Bound a review by silence, and give it room to load an epic

Status: ready-for-agent

**Blocked by:** None — can start immediately.

**What to build:** an epic-sized round stops being killed for being slow, and gets the context to load the diff at
all. Two rounds of an observed run were aborted at the server's fixed hour while still emitting events — 273 of them —
and a third was rejected before the model ran, because the diff is placed in the review's prompt by the harness. One
bound gives the review time to walk the input and one setting gives it room to hold it; neither alone was enough.
Settled as D7, D8, D9, D10 and D22 in `../spec.md`.

- [ ] A review is aborted after thirty minutes with no event, and at four hours absolute, whichever arrives first.
      The idle figure is a judgement rather than a measurement and the constant's own comment says so: the average gap
      it was first argued from says nothing about the tail it meets, and the maximum was never recorded.
- [ ] The idle clock resets on every event the backend reports, the liveness observer's included.
- [ ] A failed round's reason names which of the two bounds ended it, and keeps the `deadline_exceeded` code ticket 03
      gives both bounds wherever that has already landed. The two tickets rewrite the same sentence: whichever lands
      second keeps the other's clause.
- [ ] The published deadline figure keeps its name and reports the hard cap; no key is added.
- [ ] What the status tool says that figure *means* stops calling it the ceiling the review is aborted at — the idle
      bound makes that false in the ordinary case — and names both bounds instead. D8 keeps the idle bound out of the
      payload, so this description is the only place a caller can learn it exists before a round ends on it.
- [ ] Both bounds are the server's own constants, declared beside its others and handed to the lifecycle the way the
      single deadline already is. No host configuration reaches either.
- [ ] The manifest's default review model carries the one-million-context suffix: the string is `opus[1m]`, the alias
      with `[1m]` appended. The server appends nothing to a model an owner named — which is how it already reads the
      option, verbatim, and stays that way. Measured: the suffix is accepted on the opus and sonnet aliases and refused
      outright on haiku.
- [ ] The README's stated default for the review model matches the manifest.
- [ ] Both descriptions of that option — the manifest's, which is what the configuration dialog shows, and the
      README's — say what the suffix buys and that an owner who names a bare alias gives it up. Both currently offer
      `opus`, `sonnet`, `haiku` and invite an override; an epic-sized diff is the case the suffix exists for, so an
      override taken without that sentence walks straight back into the rejection this ticket removes.
- [ ] ADR-0007 says the bound is an idle timeout plus a hard cap, and why — a review still emitting events is not the
      failure the bound exists to catch. One review at a time, and no owner-tunable bound, are unchanged.
- [ ] Its grounds go with it: the sentence arguing that a round measured near two minutes puts a fixed ceiling of an
      hour "far above anything observed" is the reasoning the observed run refuted, and cannot stand beside the
      amended lead.
- [ ] The amendment says what changed and why, because a decision changes in the one place it lives.
- [ ] Both bounds are checked with a fake clock and small numbers at the lifecycle's existing injection point, by hand
      and not committed, plus the scripted-backend lifecycle, `typecheck` and `lint`.

**Triage, 2026-08-23 — stays `ready-for-agent`; five criteria added or widened.**

The claim holds at the code path. `config.ts`'s `DEADLINE_SEC` is a fixed hour and the only bound there is;
`lifecycle.ts`'s `arm()` sets one timer at start and never rearms it on an event, so a round emitting 273 events is
aborted at the hour exactly as the run showed — there is no clock to reset and no cap above it. The reset the second
box asks for reaches an existing seam: the liveness observer emits `running` through the same `emit` the lifecycle
wires, so every firing already arrives where the idle clock would live, and the lifecycle already takes its bound and
its clock as injected dependencies, which is the fake-clock injection point the last box names. Nothing here is built:
no idle bound, no cap, and no `[1m]` anywhere in `plugin/`. No prior rejection of this shape is on record; the
repository keeps no `.out-of-scope/`.

One interaction checked and cleared, so it is not re-raised: four hours does not cross the store's TTL. `store.ts`
evicts terminal records only, so a four-hour review is never dropped out from under its own in-flight slot — which
would have held that slot for the life of the process, since `clearInFlight` runs only from an event that finds its
record. Four hours also stays inside `MAX_TIMEOUT_MS`, so the clamp and its comment remain accurate.

Five defects in the criteria, now fixed:

- **The published figure's own description would have gone false under a ticked box.** Two places say what
  `deadlineSec` means, and the status tool's — the one a caller actually reads — calls it "the ceiling this review is
  aborted at". After the idle bound that is wrong in the ordinary case, and "keeps its name and reports the hard cap"
  is satisfied by changing one number and leaving it. D8 deliberately keeps the idle bound out of the payload, which
  makes that description the only place a caller can learn it exists before a round ends on it.
- **The literal suffix was written down nowhere.** Neither this ticket nor `spec.md` states the string every box in the
  model group turns on; it appears in this repository only as `.claude/settings.json`'s own model and CONTRIBUTING.md's
  tree comment, both of which say how *this repo* runs Claude Code, not what the plugin ships. An implementer was left
  to infer it, and a wrong guess ships a manifest whose default fails every review at the owner's expense — against a
  measurement nobody can re-run cheaply. Named in the box.
- **Both descriptions of the model option stay silent about what the override costs.** The box covered the README's
  stated *default* only. The manifest's description is what the configuration dialog shows, it offers `opus`, `sonnet`,
  `haiku` and invites an override, and an owner who takes it up gets the bare alias — the rejection this ticket exists
  to remove — with nothing warning them. That is D10's accepted trade, and the dialog is the one place to state it.
- **The reason clause did not keep ticket 03's word.** 03 carries the pairing from its side — both bounds end on
  `deadline_exceeded`, with the text saying which — but 04 said only "names which of the two bounds ended it". An
  implementer landing 04 second rewrites that sentence with no reason to keep the prefix, and 03's closed vocabulary
  silently loses its word for the failure that killed half the observed run. Now symmetric.
- **ADR-0007's grounds still argued for the hour.** The amended lead would sit above a sentence reasoning that a round
  measured near two minutes puts a fixed ceiling of an hour far above anything observed, which is precisely what the
  run refuted. Same defect class 01 fixed on ADR-0005: an amendment whose grounds contradict it.

No glossary work: D23 settled it, and nothing above needs a term `CONTEXT.md` does not already carry.
