# 12 — Say what the plugin does on the reader's forge

Status: ready-for-agent

**Blocked by:** 02 and 05 — the narrower promise is only true once both have landed.

**What to build:** a reader deciding whether to use this plugin on their forge learns what it actually does there. The
README promises "two rounds of code review, with the findings raised as comments and then fixed", which was measured
false on a forge where the reviewer prints its findings instead of posting them — and is now true only because the
review is instructed to post, with the prose reaching the fix wave when it does not. Settled as D24 in `../spec.md`.

- [ ] The findings-as-comments promise says what the forge allows: raised as comments where the reviewer can raise
      them, and fixed either way. The settled wording is *"two rounds of code review, with the findings raised as
      comments where your forge lets the reviewer raise them, and fixed either way"*. "Your forge" is the README's own
      phrase, already carrying the forge CLI examples in the requirements list.
- [ ] Nothing is promised about a finding being *named* anywhere. It is not: a fix wave's report carries its commits,
      the findings it declined, its **hand-offs** and whether the **checks** ended green, and the closing report
      carries "every finding the fix waves declined" — a finding that gets fixed appears in neither. The closing-report
      bullet already promises the declined half for every finding, and is unchanged.
- [ ] The bullet keeps the count — **two** rounds, and that they are code review. The README nowhere ties that count
      to the flip out of draft, and does not gain the tie here.
- [ ] Nothing in the README conditions behaviour on which forge is in play; the requirements section's forge CLI
      examples stay as illustrations. A capability the reader's forge either has or lacks is not a named forge.
- [ ] Nothing promises anchoring. A guard rather than a change — the README does not promise it today, and the spec
      puts it out of scope on a forge that will not anchor.
- [ ] The adjudication bullet immediately below is ticket 11's, which narrows it to the implementation stage. It is
      untouched here, and neither ticket reflows the other's lines; they land in either order.
- [ ] The register is matched — the README is written for a human choosing a tool, not for a model.
- [ ] The file's prevailing column width is matched: 120, with its longest lines sitting exactly on it. Count
      characters, not bytes — the file's em-dashes are three bytes each.
