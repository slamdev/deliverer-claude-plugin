# 02 — Instruct the review to post its findings on whatever forge

Status: ready-for-agent

**Blocked by:** 01 — the decision above this prose says the reviewer posts its findings unaided.

**What to build:** a round driven against a change request on a forge whose reviewer would otherwise print its findings
to a terminal nobody reads instead posts them as comments the forge can mark **resolved**. The instruction is appended
by the tools server to the review prompt it already builds, so no caller gains an input and no `code-reviewer` can
change what a review is. That driver's own definition asserts the posting as a fact of what a round does, in the same
shape the decision above it does, so it says instead what this ticket makes true. Measured during the grilling: three
findings and zero comments before, three findings and three resolvable comments after, with the forge's own inline
mechanism undisplaced where it has one. Settled as D1 and D2 in `../spec.md`, which carries the wording.
