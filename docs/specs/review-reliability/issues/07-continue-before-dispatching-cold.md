# 07 — Continue an agent that stopped, before dispatching a cold one

Status: ready-for-agent

**Blocked by:** None — can start immediately.

**What to build:** an agent that stopped without a **report** is continued while it is still addressable, rather than
dispatched cold. A cold start re-reads the epic, the **ticket** and the codebase, which is most of what the
implementers' cache reads were, and the observed run lost 1,333,341 tokens to four agents that died mid-work.
[ADR-0015](../../../adrs/0015-the-orchestrator-forms-no-judgement.md) already settles that this is the same move as a
cold **dispatch** and differs only in cost; what is missing is the preference, in the delivery skill. Settled as D14 in
`../spec.md`.

- [ ] The delivery skill says an agent that stopped without a report is continued while it is still addressable, and
      says why: it still holds the context, where a cold start pays again to read the epic, the ticket and the
      codebase.
- [ ] A cold dispatch is what happens when the agent is no longer addressable, or when continuing it fails, so the path
      is never a dead end.
- [ ] The existing statement that dispatching any agent but `code-reviewer` cold is safe, because each one resumes on
      its own and adds only what is missing, is kept — and reads as the fallback rather than the first move.
- [ ] `code-reviewer` is continued like any other agent, and the prose says a continue opens no **round**: the agent
      carries on polling the `review_id` it already holds. The exception is about the cold path, where a fresh dispatch
      opens a fresh round under a fresh id.
- [ ] What the continuing message names is stated: what the orchestrator may already settle for itself — what the
      branch carries, whether it builds, whether the **checks** are green — and, where a stage's evidence is not the
      orchestrator's to read, only that no report arrived and the work is owed. Nothing in it has the orchestrator
      counting comments.
- [ ] The rule sits with the skill's existing sentence about putting a stage back, not inside **Resume**: that
      paragraph is the run reading its **bearings**, which is a different move from continuing a live agent.
- [ ] How a continue appears on the task list is stated: the task flips back to `in_progress` and gets no task of its
      own, because a continue is the same dispatch rather than a new one, so one-dispatch-one-task still holds.
- [ ] The bolded pair **re-dispatch or report** widens to the glossary's own phrasing — the stage goes back to an
      agent, continued or cold, or it is reported — so the skill's most emphatic statement of the orchestrator's
      options stops naming half of them.
- [ ] **Sequencing** is not widened: a dispatch that answers at once and finishes in the background already covers a
      continued one.
- [ ] No host mechanism is named — what must be true, never the tool that makes it so.
- [ ] `refine/SKILL.md` is untouched: it already carries this rule, and D14 names the delivery skill.
- [ ] Register and the file's prevailing column width are matched.

- **ADR-0015 already permits it.** Putting a stage back "is one move however it is made: continuing a dispatch that
