# 08 — The end-to-end tests assert a debrief appeared

Status: ready-for-agent

**Blocked by:** 04

**What to build:** the two happy-path tests already drive whole runs against a real forge, so a debrief is produced
whether or not anybody looks. This makes the **harness** look — shallowly and deliberately, because depth lives at the
replay seam and this one costs real money every time it runs. Settled under Testing Decisions in `../spec.md`.

- [ ] The refine and build happy-path tests assert that the run they drove left a **debrief**.
- [ ] The assertion reads the header: the right skill, the right epic **slug**, and a dispatch count consistent with the
      run the test just drove.
- [ ] The skill is the one the test drove — `refine` or `build`, the same string the builder already puts in the command
      it sends — and the slug is the run's own, read off the outcome's published **epic** rather than written down as a
      constant beside the assertion. A refinement's slug is whatever that run chose.
- [ ] The dispatch count is checked against what the **run directory** itself holds: the session records under the
      orchestrator's own `<session-id>/subagents/`, counted by this assertion. Not `SessionRecords.dispatched`, which
      counts every such record anywhere under the run's configuration directory — the **observer** runs in that same
      directory, so its own **dispatch note**s would land in that figure. This makes the criterion a cross-check of the
      debrief against the host's own files rather than against a constant the skills can outgrow.
- [ ] The debrief is found at a path the harness derives: `plugins/data/<plugin>-<marketplace>` under the run's own
      configuration directory, which is inside the run directory because the harness pins `CLAUDE_CONFIG_DIR` per run.
      Both names are already read off the marketplace entry, and the host's mangling of them into one directory name is
      a **claim** in the glossary's sense exactly as the record format is — so the failure names the path it looked at
      and what it derived it from, and a host that renames its data directories fails there rather than reading as a run
      that produced no debrief.
- [ ] The debrief is read the moment the run returns, with no wait and no poll. D23 keeps a readable one current as each
      stage lands, so there is nothing to wait for; the assertion says which state it read. It rests on ticket 04
      rewriting the debrief atomically, which that ticket now requires.
- [ ] A missing debrief fails the test with the **run directory**'s path quoted, so the failure is read there rather
      than reproduced.
- [ ] The assertion adds no measurable money and no measurable time, and the **ceiling**s are unchanged.
- [ ] The harness does not switch observation off, and does not configure it — it meets the default a user meets.
      Nothing switches it on either: the run's first prompt is already `/deliverer:refine …` or `/deliverer:build …`,
      which is ticket 04's own trigger, so the observer starts with no change to the harness at all.
- [ ] Nothing the observer wrote appears inside the fixture repository, the clone or the change request the test
      produced.
- [ ] `e2e-tests/README.md` says that the observer runs during both paid tests, that it draws on the same account as the
      run, and that its **spend** is in none of the figures the harness reports — so every amount recorded there
      under-counts a run by whatever the observation cost. It is the same shape of gap that file already records for a
      **round**'s review spend.
- [ ] The harness is typechecked and linted as CI already does, and no end-to-end test is added to CI.

**Triage, 2026-08-26 — stays `ready-for-agent`; five criteria added, one extended, none removed.**

Nothing here is built. The search was by concept rather than by the request's wording — `debrief`, `observer`, `trace`,
`replay`, `distill` across every source, manifest, hook and document outside `docs/specs/` — and no assertion about a
debrief exists anywhere in `e2e-tests/`. The `observ` matches there are the harness's own vocabulary (`ObservedRun`,
`observeSession`, `McpServerObservation`) and unrelated. No prior rejection of this shape is on record; the repository
keeps no `.out-of-scope/`.

**Four facts this ticket rests on were checked against the harness and the host, and all four hold.**

The debrief lands *inside* the run directory already. The host installs a plugin's data directory at
`<config>/plugins/data/<plugin>-<marketplace>` — read off this machine, where `deliverer@slamdev-deliverer` is at
`plugins/data/deliverer-slamdev-deliverer` — and `harness/run-directory.ts` pins `CLAUDE_CONFIG_DIR` to the run's own
directory for every process a run starts. So D18's "outside every repository" and this ticket's "quote the run
directory" are the same place, and the assertion needs no new plumbing to reach it.

Nothing needs to switch observation on. Both builders already send `/deliverer:refine …` and `/deliverer:build …` as the
run's first prompt, which is ticket 04's own trigger verbatim — so the criterion about meeting a user's default is true
by construction rather than something to arrange, and a criterion now says so, because an implementer reading "does not
configure it" could reasonably have gone looking for a switch to set.

Neither of the harness's own agents can start an observer. `harness/agent.ts` runs the **responder** and the
**verifier** with `settingSources: []`, so no plugin loads in their sessions and no hook of this plugin's fires. That
matters because the plugin is installed at user scope in the run's configuration directory, which those agents share.

The assertion's three inputs all exist. Both outcomes carry `epic.slug`, `ObservedRun` carries the run directory and the
records, and the skill is the builder's own `TEST_NAME`.

**Four decisions were the maintainer's.** The debrief is found by **deriving** the path from the plugin and marketplace
names the harness already reads, rather than scanning the data root for it — which makes the host's name-mangling
something the harness pins, so the criterion requires the failure to name both the path and what it was derived from,
and records the mangling as a claim rather than a contract. The debrief is **read at once**, with no wait for the
finalise and no poll, since D23 keeps a readable one current; the finalise race is answered on the other side instead,
by requiring ticket 04's rewrite to be atomic — added there, since "a readable one exists at every moment" is what that
ticket already means. The dispatch count is checked against the **run directory's own dispatch records** rather than a
constant, which turns the vaguest of the original criteria into a mechanical cross-check of the observer's **trace**
against the host's files. And `e2e-tests/README.md` **gains the disclosure**, because that file's whole subject is how
to work out what a run cost and every figure in it is about to under-count one.

**One consequence the maintainer left standing, recorded so it is not lost.** `SessionRecords.dispatched`
(`harness/run.ts`) counts any path containing `subagents` anywhere under the run's configuration directory. The observer
runs in that same directory and writes up to thirteen **dispatch note**s, so once observation is live that figure may
include work no run dispatched — which weakens, without failing, the floor `assertSessionRecordsKept` holds in both
happy-path tests. Scoping that helper to the run's own session id was weighed and declined here: this ticket's new
assertion does its own scoped count instead and touches no existing matcher. If the floor is later wanted tight again,
that is the one-line change.

`CONTEXT.md`'s **Verification** section gained a **Ceiling** entry in passing. The term was already bold in this
ticket's own last criterion, is what `harness/ceilings.ts` and `e2e-tests/README.md` are largely about, and had no
glossary entry — which under `.claude/CLAUDE.md`'s rule is a gap rather than invented language. The entry carries the
distinction that file opens with, that reaching a ceiling is not a failing assertion, and the fact this ticket needs:
that what a run spends out of band — a round's review, now an observer — is not in it.
