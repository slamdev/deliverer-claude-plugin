# A debrief is bounded to the plugin's own machinery

A **debrief** names the plugin and its conduct — the skills and agents that ran, the **dispatch**es, what each stage
took, the **spend**, the **rounds** and how the **run** ended — and never the repository the run was delivering into. No
code, no **spec** prose, no **ticket** text, no **comment**, nothing from the forge. A **defect**'s **grounds** come
from the **trace**, which is a record of the plugin's own behaviour, so the bound costs a defect nothing it needed.

A debrief exists to be forwarded to whoever maintains the plugin. A document that has to be read for leaks before it
can be sent is a document that does not get sent, and this bound is the whole reason one can be forwarded unread. The
sharper defect that repository context would buy is declined on that ground: the cost of getting it wrong is somebody
else's proprietary code arriving in a maintainer's inbox, it falls on the user rather than on the maintainer, and
nothing about it is loud.

A **run**'s conversation with its human is bounded the same way, and there the bound is shape rather than words. A
refinement works its **frontier** in question rounds, and what those rounds cost the human is the whole reason this
exists — so a debrief counts them, times them, names the subject one turned on and says which earlier round or **sweep**
had already covered it. It quotes neither the questions nor the answers. The human's answers are their product decisions
outright, and a question the orchestrator generated from somebody's **idea** carries their domain inside it, so quoting
the plugin's own output would disclose the user by another route.

The installed plugin's own text is inside the bound. Quoting the line a run diverged from names the plugin, not the
repository, and a defect that points at the file it is about is the difference between a debrief and an anecdote.

The epic's **slug** is the one thing of the user's own domain that a debrief carries, and it is carried deliberately:
debriefs are grouped by it, and one that cannot say which epic it is about is one nobody can act on. It is therefore the
one field a human forwarding a debrief is told to read first.

What holds the bound is instruction, and that is a decision rather than an oversight. The **trace** an **observer**
judges carries excerpts of what the records carried, tool inputs and outputs among them, so the observer sees the
repository even where the debrief may not name it: nothing distils that content out beforehand, and no second reader
checks a finished debrief before it is called sendable. Both were weighed and declined — a mechanical bound costs a
**defect** the **grounds** it rests on, and an independent checker is one more agent on every run. So the failure mode
is a debrief that quotes what it should not while saying on its face that it is safe to forward. Adding a check later
is an improvement and not a reversal; assuming one is already there is the mistake this paragraph exists to prevent.

The trace is kept beside the debrief and carries no promise of its own. It is not the document to forward, and it says
so in its own first line, in its name, and wherever the debrief mentions it.

The trap this is written against: the obvious way to improve any debrief is to give it more context, and that is exactly
what is forbidden. A future contributor pasting a diff excerpt in to make a defect clearer has not improved the debrief.
They have made it unsendable, and the users who learned it was safe to forward will not be told.
